# RescueMesh frontend

Synthetic simulation. This branch implements the D1 frontend shell (PRD §12.3),
with a deliberately quiet incident view, three expandable agent roles, and one
tabbed area for activity, proposals and resources. The default **FIXTURE** mode
contains no model-generated negotiation or simulated outcome numbers.

## Run

```sh
npm ci
npm run dev
```

Open http://127.0.0.1:5173. Load a preview, change presets, expand agent roles,
switch the detail view, and inspect the fixture event. Escape closes the inspector
and returns focus to its trigger. The actual scene belongs to Madhav; the contour
background is decorative and explicitly labeled as a placeholder.

`Connect simulator` reads `/health` and `/state`, then subscribes to named SSE
events. The default backend URL is `http://127.0.0.1:8000`; override it with the
public `VITE_API_BASE` setting. `VITE_API_BASE=/api npm run dev` uses the local Vite
proxy to port 8000. No API credentials belong in the frontend.

The backend must already have an active run. Tisha's current scaffold supports
`POST /scenarios/hello-fixture/reset`; its stepper is a stub, not wildfire physics.
An absent provider/model is displayed as **BACKEND PREVIEW**, never live agent output.
The shell only observes backend runs; negotiation and simulation action buttons
remain disabled until their services and UI state handling are integrated.

## Verify

```sh
npm test                  # pure stream-reducer checks
npm run test:e2e          # reducer + real Chrome interaction checks
npm run build
npm run lint
```

Browser checks use installed Google Chrome (`channel: 'chrome'`) and labeled,
intercepted backend responses. They cover fixture labeling, preset selection,
inspector focus, compact/mobile overflow, connection errors, and named SSE
deduplication/run isolation. Screenshots are in ignored `test-results/`.
They do not verify a live agent negotiation, simulation, or benchmark result.

## Integration boundaries

- `src/types.ts` is generated by WS-C and is never hand-edited. `ScreenState`
  projects its fields for rendering; payload validation currently checks only
  the fields the D1 shell reads.
- `src/api.ts` contains HTTP and isolated fixture adapters. Fixture IDs are
  prefixed `ui-preview-`; preview reset never calls backend reset.
- `src/stream.ts` parses envelopes, reduces independent incident/benchmark cursors,
  rejects malformed/duplicate/wrong-run events, and requests a fresh snapshot on
  `snapshot.required`. Native EventSource retains Last-Event-ID on reconnect.
- `src/components/shell-data.ts` holds display copy/projections and the temporary
  envelope interface pending WS-C's generated Envelope/Health exports.
- `src/App.tsx` orchestrates the shell; no simulation rules or acceptance decisions
  exist in the UI. D2 fills the proposal/resource panels and agent states from
  agreed fixtures. D3 mounts `IncidentViewer` and `EnvironmentalControls` from
  Madhav's `src/simulation/` and completes transport recovery/polling.

Design: slate surfaces, restrained agent colors, local Avenir/system font stack,
details on demand, minimal motion, visible keyboard focus. No external fonts,
charts, image downloads, or UI component library are required.
