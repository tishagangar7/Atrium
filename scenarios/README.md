# Scenarios (WS-A, Madhav)

Every tuneable number for the PRD world lives here, never as a constant in code
(AGENTS.md section 7). The *rules* live in the simulator; the *values* live in
these files, so the G2 tuning gate (PRD section 5.13) can change behaviour
without touching code.

## The `extends` convention

A disruption preset carries only its identity and its `events`, and inherits
everything else:

```json
{
  "schema_version": "1",
  "scenario_id": "road_closure",
  "extends": "normal.json",
  "title": "West Forest fire - R3 lost at step 15",
  "events": [
    { "event_id": "ev-road-15-r3", "step": 15, "kind": "road_status",
      "target": "R3", "value": "CLOSED_HARD", "public": true }
  ]
}
```

`resolveScenarioDocument` in `frontend/src/simulation/prd/scenario.ts` walks the
chain and merges base first, so the extending document's own keys win. Tuning
the map therefore means editing `normal.json` once.

A `wind_change` event sets one field at a time, so a shift in both direction and
speed is two events sharing a step. This keeps each event inside the PRD
section 7.2 `ScheduledEvent` shape, which carries a single `target` and `value`.

## The compact `cells` block

Writing all 60 cells out by hand invites drift, so the file states the rule and
the loader expands it:

```json
"cells": {
  "fuel_default": 0.7,
  "fuel_overrides": [
    { "cells": ["c7_2", "c9_2", "c6_5"], "fuel_initial": 0.2 },
    { "cells": ["c1_1", "c2_1", "c1_2", "c2_2"], "fuel_initial": 0.9,
      "fuel_initial_prior": 0.5 }
  ],
  "firebreak_bonus": ["c2_1"],
  "initial_fire": [{ "cell": "c0_2", "intensity": 2 }]
}
```

Later overrides win. The expanded result is a `cells` map of 60 entries in the
PRD section 7.2 `Cell` shape. `backend/tests/test_sim*.py` and
`frontend/src/simulation/tests/prd-scenario.test.ts` both pin the expansion
against the PRD tables.

## Public priors

Fields a single agent knows privately carry their public value alongside the
true one, so a belief view can be built without a second file:

- `roads[].public_prior_status`
- `zones[].assisted_initial_prior`
- `shelters[].background_prior`
- `cells.fuel_overrides[].fuel_initial_prior`
- `cells.firebreak_bonus_prior`

The authoritative world always uses the true value. `BeliefView(agent)`
(PRD 5.9) substitutes the prior for every item that agent does not hold. That
masking is implemented in code, never by prompt wording (invariant 5).

## Changing a value

1. Edit the JSON, not the code.
2. Record what changed and why in `CHANGELOG.md`.
3. Re-run `npm test`; the scenario tests pin the PRD tables and will fail loudly
   if a value drifts from the specification by accident.
4. Before G2, `scenarios/tune.py` must still pass the three checks in PRD 5.13.
